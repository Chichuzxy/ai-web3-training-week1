## 实验 1: Temperature 对代码生成的影响

### 测试 Prompt（固定不变）
```
请写一个 Python 函数，检查一个字符串是否是回文（正反读一样）。
只写函数体，附带类型注解。
```

### 结果记录

| Temperature | 输出特点 | 评价 |
|-------------|---------|------|
| **0.1** | 最标准的实现：`return s == s[::-1]`，直接、无冗余 | 代码精准，但注释极少 |
| **0.5** | 加了 docstring 和基本错误处理，风格均衡 | 适合作为项目模板 |
| **0.9** | 给出了多种实现方式（递归、迭代、切片），附了大量解释 | 适合学习，但不够简洁 |

### 结论
- 代码生成任务用 **Temperature ≤ 0.4** 最安全
- 调试/分析场景用 **Temperature ≤ 0.3**
- 只有在学习/头脑风暴时才需要高温度（>0.7）

## 实验 2: Max Tokens 对回答完整性的影响

### 测试 Prompt（固定不变）
```
请用 300 字以内解释以太坊的 Gas 机制，包括：什么是 Gas、为什么需要 Gas、Gas Price 和 Gas Limit 的区别、以及 EIP-1559 改革后 Fee Market 的变化。
```

### 结果记录

| Max Tokens | 输出情况 |
|-----------|---------|
| **200** | ❌ 回答被截断，没讲到 EIP-1559 |
| **500** | ✅ 覆盖全部要点，但最后一句不完整 |
| **1000** | ✅ 结构完整，有清晰分段和总结 |

### 结论
- 对于结构化知识解释，**Max Tokens ≥ 1000** 通常足够
- 如果要求 "X 字以内"，模型会自行控制长度，无需设过低的 Max Tokens
- Max Tokens 设太小是新手最常见的坑——导致回答被硬截断

## 实验 4: System Prompt 的影响

### 不带 System Prompt
Prompt 仅："解释什么是智能合约"  
→ 输出偏教科书式，语言正式但冗长

### 带 System Prompt
System: "你是一个友好的 Web3 助教，善于用类比解释复杂概念。回答不超过 200 字。"  
Prompt: "解释什么是智能合约"  
→ 输出简短有力，用了"自动执行的协议"类比，更贴近用户需求

### 结论
- System Prompt 的力量 > 在用户 prompt 中重复描述角色
- **最佳实践：** 角色设定 + 行为准则 + 禁忌清单 放在 System Prompt 中
- 用户 prompt 只包含具体任务

---

## 关键发现总结

1. **Temperature 选低不选高** — 教学场景中，准确性远比创造性重要
2. **Max Tokens 宁可大不可小** — 短了会被截断，大了最多浪费一点 token
3. **System Prompt 是最强的提示词** — 把规则和角色放这里，一次设定永久生效
4. **没有"万能配置"** — 不同任务需要不同的参数组合，需要根据反馈调整
