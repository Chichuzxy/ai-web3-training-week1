## 地图总览

将 AI × Web3 交叉方向按"问题域"而非"热门项目"组织。每个方向用统一框架判断：AI 不可替代什么，Web3 不可替代什么，以及它们交汇处真正解决的问题。

| # | 方向 | 核心痛点 | AI 角色 | Web3 机制 | 不可替代性判断 |
|---|------|----------|---------|-----------|----------------|
| 1 | Payment / Commerce | Agent 如何自主完成 API/数据/算力的购买、验收、结算 | 理解报价条款、规划预算、自动执行付款 | 链上结算、x402/MPP 支付协议、链上收据 | AI=自动识别支付条件+决策; Web3=无需银行账户的机器支付轨道 |
| 2 | Identity / Reputation | Agent 如何被发现、描述、验证、协作、建立信誉 | 生成能力声明(profile)、解析任务需求、匹配协作对象 | DID/ENS 身份、EAS 链上证明、ERC-8004 agent registry | AI=动态能力匹配; Web3=去中心化身份+可验证声明 |
| 3 | Wallet / Permission | Agent 接触私钥/签名/资金时，权限如何分层、限制、撤销 | 解析自然语言意图→权限策略、风险评估、异常检测 | AA 智能账户、Safe Guard/Policy、CAW Pact 任务级授权 | AI=意图→权限边界翻译; Web3=链上强制执行+不可绕过 |
| 4 | **Privacy / Security**  ← 主方向 | AI 推理数据隐私、合约漏洞、prompt injection、模型被盗 | 生成 ZK 证明、检测异常模式、审计代码 | ZK 链上验证、TEE 可信执行、链上不可篡改审计日志 | AI=生成证明+检测; Web3=公开可验证+无信任第三方 |
| 5 | Governance / Coordination | DAO 信息过载、提案质量低、贡献难以追踪 | 提案摘要、会议→行动项、贡献统计、预算 checklist | Snapshot 投票、链上执行记录、公开 accountability | AI=信息处理+提醒; Web3=透明执行+抗审查投票 |
| 6 | Agent DeFi Execution (应用路径) | Agent 执行 swap/lend/stake 时的安全边界 | 市场分析、策略优化、异常检测 | 链上清算、Pact 预算限制、审计日志 | AI=策略生成+风险预警; Web3=链上执行约束+可审计 |

## 方向详情

### 1. Payment / Commerce / Settlement

**一句话:** AI agent 需要自己的"支付宝"，但关键是预算控制、交付验收、争议处理，不只是转账。

**AI 不可替代:**
- 自动识别服务报价条款（自然语言→结构化条件）
- 在授权预算范围内做支付决策
- 判断交付结果是否满足验收标准

**Web3 不可替代:**
- 机器对机器的链上支付轨道（无需银行账户）
- x402/MPP: 标准化的 paywall + 收据协议
- 链上结算记录不可篡改

**层级判断:** 协议层 + 应用层

**不是纯 AI 的理由:** AI 可以生成付款请求，但没有 Web3 的链上结算，跨服务商支付需要接入每个平台的 API，无法形成开放协议。

**不是纯 Web3 的理由:** 区块链能做转账和收据，但无法自动理解报价条款、判断交付质量、处理争议——这些需要 AI 的判断和规划能力。

**典型场景:** Agent 帮用户购买一个收费的数据 API → 自动识别 x402 paywall → 在预设预算内付款 → 获取数据 → 验证数据完整性。

---

### 2. Identity / Reputation / Capability

**一句话:** Agent 不只是"能跑的代码"，需要可发现、可调用、可信赖的 profile 层。

**AI 不可替代:**
- 自动生成和维护 agent 能力声明（capability manifest）
- 动态匹配任务需求与 agent 能力
- 从链上历史推断 agent 信誉

**Web3 不可替代:**
- ENS/DID: 去中心化身份，不依赖单一平台
- EAS: 链上可验证证明（谁声称了什么，谁验证了）
- ERC-8004: agent 注册和发现标准

**层级判断:** 协议层 + 标准层

**不是纯 AI 的理由:** AI 生成的 profile 如果存在中心化数据库里，平台倒闭 agent 信息就丢了。Web3 让 agent 身份跨平台持久存在。

**不是纯 Web3 的理由:** 链上一个 NFT 名片不能自动说出 agent 能做什么——需要 AI 生成和维护能力声明、匹配任务和评价交付质量。

**典型场景:** 在 agent marketplace 中发现一个能做合约审计的 agent → 查看链上 EAS 证明（by who, when, what）→ AI 根据任务复杂度匹配合适的 agent。

---

### 3. Wallet / Permission / Safe Execution

**一句话:** Agent 碰钱包不是"能不能签名"的问题，而是权限的授予、限制、撤销、审计闭环。

**AI 不可替代:**
- 自然语言意图 → 结构化权限策略（Pact）
- 实时风险评估（交易 vs 历史行为模式）
- 异常检测和人工确认触发

**Web3 不可替代:**
- 智能账户(AA) + Guard/Policy: 链上强制执行的权限规则
- CAW Pact: 任务级临时授权，任务结束自动失效
- 链上审计日志不可篡改

**层级判断:** 安全层 + 应用层

**不是纯 AI 的理由:** AI 可以做风险评估，但不能在链上强制执行权限限制——Web3 的 Guard 合约在协议层拦截越权操作。

**不是纯 Web3 的理由:** Guard 合约需要精确的规则（哪个合约、多少金额、什么时间），普通用户不会写——AI 把"帮我用 100U 在 Uniswap 换 ETH"翻译成精确的 Pact。

**典型场景:** 用户说"帮我在 Uniswap 用不超过 0.5 ETH 换 USDC" → AI 生成 Pact(预算=0.5ETH, 合约=Uniswap Router, 动作=swap, 时间窗口=1h) → CAW 执行，超出范围自动拒绝。

### 4. Privacy / Security / Sovereignty ← 主方向

**一句话:** AI 推理要保护用户数据隐私，同时让结果可验证——ZKML 是交汇点。

**AI 不可替代:**
- 链下运行推理模型（高算力需求）
- 生成 ZK 证明（证明推理正确执行）
- 检测异常行为和潜在攻击

**Web3 不可替代:**
- ZK Verifier 合约：链上公开验证 proof，不暴露输入
- TEE 可信执行：硬件层保护模型参数
- 链上审计记录：谁何时做了什么

**层级判断:** 安全层 + 协议层

**不是纯 AI 的理由:** AI 能推理和生成结果，但无法向第三方证明"结果确实是这个模型用这个输入算出来的"——需要 ZK 密码学。

**不是纯 Web3 的理由:** ZK 可以在链上验证"某个计算执行了"，但 AI 推理的高算力需求无法在链上完成——必须链下推理+链上验证的混合架构。

**典型场景:**
1. 医疗：患者提交症状数据 → AI 链下诊断 → ZK 证明诊断正确 → 保险合约自动理赔
2. 金融：用户提交信用数据 → AI 链下评分 → ZK 证明评分过程正确 → 贷款合约自动审批
3. DeFi：AI 分析链上数据生成交易策略 → ZK 证明策略逻辑 → 策略市场交易

**反例:** 如果只是"AI 帮用户填一个加密表单然后提交到链上"，没有 ZK 证明推理正确性——这只是自动化，不是 ZKML。

---

### 5. Governance / Coordination / Public Goods

**一句话:** AI 不应替代治理决策，但可以帮助整理信息、追踪贡献、辅助透明执行。

**AI 不可替代:**
- 提案摘要和讨论脉络整理
- 会议 → 行动项 + owner + deadline
- 贡献数据统计和预算执行 checklist

**Web3 不可替代:**
- 公开可验证的投票记录
- 链上透明预算执行
- 抗审查的提案和讨论空间

**层级判断:** 工具层 + 治理流程层

**不是纯 AI 的理由:** AI 可以总结提案，但无法保证提案本身没有被篡改、投票没有被操控——需要链上记录。

**不是纯 Web3 的理由:** 链上投票是透明的，但无法自动读懂 50 页提案文档并生成摘要——需要 AI。

**典型场景:** DAO 收到一份 30 页治理提案 → AI 生成 1 页摘要（保留原文链接）→ 社区讨论 → AI 整理赞成/反对论点 + 建议行动项 → 人工确认后进入 Snapshot 投票。

**治理边界（AI 不能做的）:**
- 价值判断（这个提案对社区好不好）
- 预算批准（多少钱花在哪）
- 惩罚/激励决策
- 代表社区发起不可逆动作

---

### 6. Agent DeFi Execution（应用路径）

**一句话:** 把 Payment + Wallet + Privacy 放到 DeFi 链上执行场景中集中检验。

**AI 不可替代:**
- 市场分析、策略优化
- 交易前模拟和风险预警
- 自适应滑点和 gas 优化

**Web3 不可替代:**
- 链上执行（swap/lend/stake/borrow）
- Pact 预算和操作范围限制
- 链上审计 + 异常告警

**层级判断:** 应用层（继承 Payment/Wallet/Privacy 的协议和安全层）

**不是纯 AI 的理由:** AI 可以生成交易策略，但没有链上 Pact 限制，agent 可能擅自调用危险合约或超预算。

**不是纯 Web3 的理由:** 链上合约可以执行交易，但不能自动判断"现在是换仓的好时机吗"——需要 AI 的市场分析。

**高风险动作（必须人工确认）:**
- 无限 approve
- 高杠杆借款
- 治理投票
- 合约升级
