## 一、Prompt 设计原则

### 核心规则（写在前头）

1. **明确角色** — 告诉 AI "你是什么"（专家、助教、代码审查员...）
2. **限定范围** — 说清楚"做什么"和"不做什么"
3. **指定格式** — 要求输出为 markdown / JSON / 表格等具体格式
4. **给示例** — 一个 good example 胜过十句描述
5. **设安全边界** — 涉及 Web3 时强调测试网、禁止主网操作

### Prompt 基本结构模板

```
[角色设定] + [任务描述] + [约束条件] + [输出格式要求] + [示例（可选）]
```

## 二、概念解释类 Prompt

### 模板 A：基础概念速解

```
请用通俗语言解释 "[概念名]"。

要求：
1. 一句话定义这个概念
2. 用一个生活中的类比帮助理解
3. 结合 Web3/AI 场景给出实际例子
4. 列出 2-3 个常见的混淆点
5. 最后用一句话总结
```

### 模板 B：深度对比分析

```
请对比以下两个概念/技术的异同：

A: [技术 A 名称]
B: [技术 B 名称]

请从以下维度分析：
- 核心原理差异
- 适用场景
- 优缺点
- 在 Web3/AI 交叉领域的应用案例
- 学习成本

最终给出选择建议：什么时候用 A，什么时候用 B。
```

## 三、代码生成类 Prompt

### 模板 C：CLI 工具生成

```
请帮我写一个 CLI 命令行工具，功能：[功能描述]。

技术要求：
- 语言：Python / JavaScript / Go（选最适合的）
- 可直接运行，无需额外依赖（或使用 pip install 即可安装的包）
- 包含错误处理（try-except）
- 附带关键注释
- 输入参数需要用户确认后再执行敏感操作
- 如果涉及区块链操作，严格使用测试网地址

输出要求：
1. 完整可运行的代码文件
2. 简要使用说明
3. 如何测试的指引
```

### 模板 D：智能合约辅助

```
我需要 [合约功能描述]。

请注意：
- 这是教学/测试用途，目标网络是 Sepolia Testnet
- 只写最简实现，不做生产级安全防护
- 标注每个函数的 public view payable 等可见性修饰符
- 用 NatSpec 格式写函数文档
- 提示哪些部分在实际部署时需要补充安全检查
```

### 模板 E：Debug 排错

```
我遇到了以下问题：

环境：[操作系统 / Python版本 / 依赖]
错误信息：
```
[粘贴完整错误堆栈]
```

我的代码：
```
[粘贴相关代码片段]
```

请帮我：
1. 分析可能的原因（按可能性排序）
2. 给出逐步排查方案
3. 提供修复后的代码
4. 说明为什么这样改能解决问题
```

## 五、AI × Web3 专项 Prompt

### 模板 H：交叉实验设计

```
我想做一个 AI x Web3 的最小交叉实验。

我的背景：[区块链专业学生，了解基本概念，正在学智能合约]
可用资源：[Hermes Agent / 测试钱包 / Sepolia Testnet]

请帮我：
1. 设计一条完整的链路：AI 生成 → 人工复核 → 钱包确认 → 链上执行 → 浏览器验证
2. 标出每条链路的潜在失败点和回滚策略
3. 明确哪些步骤必须人工确认，哪些可以自动化
4. 推荐最简单的 MVP 实现路径
```

### 模板 I：Agent Workflow 设计

```
我想设计一个 [Agent 应用场景] 的工作流。

要求：
1. 画出流程图（用 ASCII art）
2. 列出每一步的工具调用（terminal/file/browser/search 等）
3. 标注触发条件和异常处理
4. 考虑安全性：敏感操作的人工会签机制

## 六、高级技巧

### 温度 (Temperature) 与 Max Tokens 对照表

| 任务类型 | Temperature | Max Tokens | 说明 |
|---------|-------------|------------|------|
| 代码生成 | 0.2 - 0.4 | 2000-4000 | 低温度确保逻辑严谨 |
| 创意/头脑风暴 | 0.7 - 1.0 | 1000-2000 | 高温度增加多样性 |
| 概念解释 | 0.3 - 0.5 | 1500-3000 | 适中温度平衡准确性和表达 |
| 调试分析 | 0.1 - 0.3 | 1000-2000 | 越低越聚焦具体错误 |
| Prompt 编写 | 0.2 - 0.4 | 2000-3000 | 确保 prompt 结构和语法稳定 |

### System Prompt 编写模板

```
你是一个 [角色]，专长于 [领域]。

你的行为准则：
1. [准则 1]
2. [准则 2]
3. [准则 3]

当遇到 [特殊情况] 时，请 [处理方式]。

不要做：
- [禁忌 1]
- [禁忌 2]
```

## 七、常用快捷 Prompt（复制即用）

### 快速翻译/解释英文术语

```
解释这个英文术语："[term]"。请给出中文翻译、简短定义、在 [Web3/AI] 中的用法。

### 代码 Review

```
请 review 以下代码：

```
[代码]
```

关注：
1. 是否有逻辑 bug
2. 安全性问题（特别是 Web3 操作）
3. 可读性和命名规范
4. 性能优化建议
```

### 生成测试用例

```
为以下函数生成单元测试：

```python
[函数代码]
```

要求：
- 覆盖正常输入、边界值、异常情况
- 使用 pytest 框架
- 每个测试都有清晰的 docstring
```

```

```

## 八、Prompt 工程学习笔记

### LLM 三大调参要素

| 参数 | 作用 | 建议范围 | 记忆方法 |
|------|------|----------|---------|
| Temperature | 控制创造性 vs 确定性 | 0.0 (最确定) ~ 1.0 (最发散) | 数字越大越"放飞自我" |
| Top P | 截断低概率词的选择 | 0.1 ~ 0.9 | 类似温度但作用于分布尾部 |
| Max Tokens | 最大输出长度 | 视需求而定 | 别设太小导致回答被截断 |

### Context Window 管理策略

1. **分段处理** — 长文档分 chunk 发给模型，分别处理后再合并
2. **摘要前置** — 先用模型把长文本总结成摘要，再用摘要继续对话
3. **System Prompt 精简** — 去掉冗余指令，保留核心行为准则
4. **历史消息过滤** — 对话过长时，让模型先摘要前文再续接

## 九、附录：本次课程学到的关键区别

### Prompt / Workflow / Agent 对比表

| 维度 | Prompt | Workflow | Agent |
|------|--------|----------|-------|
| 交互方式 | 单次问答 | 固定流程执行 | 自主决策循环 |
| 是否需要记忆 | 不需要 | 中间状态存储 | 长期上下文记忆 |
| 工具使用 | 无 | 预先定义的步骤 | 根据情况自主选择 |
| 适用场景 | 简单信息查询 | 重复性多步骤任务 | 复杂开放性问题 |
| Web3 类比 | 一次转账交易 | 合约内的函数调用链 | DAO 治理投票 |
